# 前瞻作为输入，而不是搜索

**副标题：** Simulation 赛道 6,807 队中第 9 名、金牌——一个在对局中从不做搜索的 7.8M 参数策略网络。

**摘要。** 两个最终提交是同一套厄诡椪–蜜集大蛇卡组、同一份权重。训练跑在一个 8 张 4090 的节点上，配 150 个 CPU actor，最终那次 PPO 用了 56 小时。做法上，每一个合法选项都先在引擎里执行一遍，把它的后果作为 28 列特征喂回去，于是网络读到的是这张卡**做了什么**，而不是去背它的 id。流程是先在 13.6 万局回放上做行为克隆，再对着一个照实时天梯重建的对手池跑 PPO。最大的单一杠杆是 rollout 规模；而在对局中加树搜索反而让智能体变弱。

感谢 Kaggle 和全体主办方办了这样一场竞争异常激烈、又精彩有趣的比赛。

## 1. 卡组：厄诡椪–蜜集大蛇

下文有两个概念要先分清。**流派**是共享同一核心的一族牌表：任何围绕多龙巴鲁托 ex 搭起来的都算 `dragapult`。**精确 60 卡卡组**是具体的那 60 张，用卡牌多重集的内容哈希来标识。8 月 12 日的竞技场里有 14 个流派，却有 148 套精确卡组，其中 15 套属于 `dragapult`。

**打法。** 纯草系能量加速。*Teal Dance* 和 *Ripening Charge* 每回合免费从手牌贴一张基本草能量，*Wild Growth* 让每一张按两份计算，两个招式又都是每能量加 30 伤害，第 3–4 回合即可一击带走 330 HP。

| 角色 | 卡 | 理由 |
|---|---|---|
| 攻手 | 4 厄诡椪 ex、2 蜜集大蛇 ex | 免费贴能加伤害成长；厄诡椪是基础宝可梦 |
| 引擎 | 大竺葵线 ×2、4 活力之森、14 草能量 | Wild Growth 让每次贴能收益翻倍；活力之森让草系宝可梦在登场当回合就能进化 |
| 稳定性 | 4 捕虫套装、4 高级球、2 宝可平板、2 小光、4 莉莉艾的决心、2 喵喵 ex | 一张卡同时补能量和宝可梦 |
| 回收 | 夜间担架、水莲的援助、2 老大的指令、审判官、不公印章、狐大盗 ex | 被击倒后把能量找回来；老大的指令负责指定下一个目标 |
| 非 ex 后手 | 2 大竺葵（140）、卡璞·哞哞（220） | 不受"仅对 ex 免伤"影响 |

**为什么选它。** 把每日回放（7 月 14 日–8 月 12 日，13.6 万局）归入这 14 个流派后，在使用最多的五个里厄诡椪–蜜集大蛇天梯胜率最高（904 局 53.9%；多龙巴鲁托 52.5%、长毛巨魔 44.1%），我取了其中使用最多的那套精确卡组，当时有 26 支队伍在用。而且牌表公开，对面经常出现完全相同的 60 张，于是可以在卡组固定的条件下直接度量策略质量。它的弱点是结构性的：主攻手全是 ex，仙子伊布的 *Safeguard* 能把它们一次全关掉。

## 2. 模型结构

整个网络如下图所示。

**Token 化。** 引擎观测被编码成 64 个 token：全局、选择上下文、场地、18 个场上位置、30 张手牌、8 张"正在查看"的卡、双方各一个弃牌堆袋、事件摘要、全局记忆，以及我方牌库中尚未露面的牌的袋。每个卡位都是一个 **CardRepr**：可学习的 id 嵌入**加上**该卡静态特征的线性投影——HP、属性、进化阶段、ex 标记，以及人工校对过的特性与招式文本语义 schema。训练时按位丢弃 id 那一半，逼迫网络只靠静态属性也能工作，于是很少见到的卡也能按其文本合理行动。5 层 pre-LN Transformer（d = 384）把序列编码成池化状态 *h*。

**选项是一等公民。** 每个合法选项都有自己的嵌入，由它自身的特征向量、以及它所指向的卡、目标、招式一起构成。这个嵌入再**对状态 token 做交叉注意力**，于是"目标：后场 3 号位"这个选项能读到该位置的实时 HP 和能量。打分是 `logit = MLP([opt, h, opt ⊙ h])`，多选提示额外经过一个计数头。

## 3. 特征工程

原则是：**把选项接地，而不是把卡背下来。** 凡是网络只能从 id 死记的东西，都写成显式数值。下表维度记作*浮点列数 + 整数卡牌/招式 id 数*；id 去查一张共享的嵌入表。

| 区块 | 维度 | 内容 |
|---|---|---|
| 全局 | 40 + 21 | 回合与动作计数、先后手标记、支援者/场地/贴能/撤退是否已用；双方牌库、手牌、奖赏、弃牌、后场数量；前场特殊状态；15 个流派的**对手卡组后验** |
| 选择上下文 | 68 + 2 ids | 提示类型（11 种）、上下文（52 种）、对数刻度的最小/最大选择数、效果卡与上下文卡 |
| 场上 ×18 | 32 + 4 ids | 是否存在/已知、HP 与已受伤害、本回合登场、能量数与属性、道具、进化深度；宝可梦、道具、能量 id |
| 手牌 / 查看 / 弃牌 / 牌库袋 | ids | 30 张手牌 id；8 张翻开的卡；弃牌堆做掩码均值；我方 60 张减去所有可见区域 |
| 事件 + 记忆 | 26 + 26 ids | 自上次决策以来：招式、击倒、被公开进入对手手牌的卡。累计：打出/贴能计数、双方各最近 4 次攻击、12 张已知卡 |
| 选项 | 60 + 28 | 类型、区域、序号、卡/目标/招式 id、归属、对数刻度计数、目标 HP 与能量——**外加 28 列引擎前瞻** |

**引擎前瞻。** 主阶段的每个选项都在引擎搜索沙盒里执行一次，读回其公开后果：造成伤害、是否击倒、拿到与丢失的奖赏、手牌与牌库变化、是否交回合、直接胜负；再加上对强制连锁和掷币的宏展开，以及一个*合法性差分*：执行之后有多少招式变得可用，于是"这张卡让蜜集大蛇的招式合法"成为显式输入，而不是要背下来的连招。隐藏区域用固定种子的填充卡代替，已验证不会泄漏；同一份探针在数据抽取、PPO actor 和线上推理中都运行。

## 4. 训练

**第一阶段——行为克隆。** 全部 13.6 万局的两侧、每个决策点都用上，每个点都跑引擎探针。天梯回放里玩家水平差距极大，所以样本要加权：赢家 1.0 对输家 0.3、10 天的时间衰减、按对局评分上调。**先训一个覆盖全部 14 个流派的共享基座**，再微调出 12 个按流派的锚点模型；剩下两个流派在天梯上太罕见，不值得单独做锚点：超级雪妖女只占 0.4% 的席位，超级妙蛙花一次都没出现。另一条路是每个流派各自从自己那一小片数据从头训，它败在数据量上：什么时候贴能、进化、撤退、用支援者，这些和卡组无关，需要整个语料才学得稳，而单一流派只占语料的百分之几（厄诡椪–蜜集大蛇占 9.7% 的席位）。

**第二阶段——价值头微调。** PPO 的优势是回报减去 V(s)，评论家一开始没校准的话，最初那几步有界更新追的就是价值误差而不是策略改进。BC 训出来的价值头不能直接用：它是在重加权的专家数据上作为辅助损失训的，从没见过策略自己会走到的状态。于是把厄诡椪–蜜集大蛇锚点的主干冻住，只有两个价值分支会动、行棋行为因此逐位不变，再用冻结策略对着对手池打 1.2 万局，把两个评论家回归到最终胜负上。

**第三阶段——PPO。** 策略就从第二阶段那个调过价值头的锚点出发；对手池是照天梯实际会喂给你的东西搭的：

- **70% — 竞技场还原。** 从开始训练那天（8 月 12 日）的回放 zip 里，我统计了每一套**精确 60 卡卡组**的占比，把排名前 40 的按原比例复现，每一套都由第一阶段中它所属**流派**的锚点模型来驾驶。比如那天最热门的一套玛俐的长毛巨魔卡组占了全部对局的 19%，于是它占这一块的 21%，由 `marnie_grimmsnarl` 锚点驾驶；其余各套一直排到 0.4%。
- **10% — 变异牌表。** 在流派内随机换 5–10 张并逐一用引擎校验，让称职的驾驶员去开一副略微跑偏的牌。
- **10% — 脚本智能体。** 主办方给的四套入门卡组，由随卡组一起提供的脚本驾驶。低分段有一部分选手会直接把主办方的脚本原样提交，所以这一块就是在直接为随机对手做准备。
- **10% — 镜像。** 自身快照，外加较旧快照组成的联赛，每 20 次更新加入一次。

变异牌表和脚本智能体这两块，对应的是天梯上从全榜均匀抽取的那 10% 对局：那里的卡组和打法都和主流环境毫不相干。

**纯自博弈从一开始就不可行**：双方都开同一套 60 张，策略只会学会打内战，而完全相同的 60 张牌在我的天梯对局里只占 4%。目标恰恰相反：让模型见过、并学会打尽可能多的竞技场卡组，所以对手池里九成都不是我这套牌。

γ 0.997，λ 0.95，clip 0.2，lr 1e-4；先知评论家驱动 GAE；奖赏差塑形与对第一阶段锚点的 KL 惩罚都在前 8 次更新内退火到零。

**决定最终模型的是 rollout 规模。** 把每次更新采集的决策数从 13.1 万提到 52.4 万时，整条学习曲线都被抬了起来，而不只是终点：在任何相同预算处，52.4 万那条都比 13.1 万高 3–6 个百分点。我据此判断 rollout 是一条值得推的轴，最终训练直接设成 **838.9 万**，是 52.4 万那档的十六倍。它前期按样本算更慢，累计 4,000 万决策时只有 0.62 的池内胜率，而 52.4 万那档已经到 0.72；但它一路涨了上去，我提交的就是它最好的那个 checkpoint：4.03 亿决策、47 小时处的 **0.83**；而 52.4 万那条在 0.72 附近走平。三条曲线如下图所示。

**为什么单位样本的效率会真的下降。** PPO 是**一步一步**改进策略的，而每一步都被封了顶——clip 0.2、3 个 epoch、KL 提前停止。策略能移动多远由信任域决定，而不是由多少数据支撑这次移动决定，所以一次训练从 D 个决策里榨出多少改进，取决于它走了多少步：rollout 为 N 时就是 D/N 步。前期优势很大（第 1 次更新平均 |优势| 0.35），52.4 万的批量就足以把这一步走满，于是十六个小步能叠加起来，而一个大步不能。累计 4,000 万决策时，52.4 万配方走了 **76** 步有界更新，838.9 万只走了 **5** 步。

**为什么天花板会升高。** 训练后期这个天平反了过来。策略已接近对手池的均衡，平均 |优势| 降到 0.16：信号缩小了，而洗牌、掷币和隐藏信息带来的方差并没有。对手池有 69 个条目，最罕见的每个只占 0.4% 的对局，52.4 万的 rollout 分给它们每人只有约 30 局。用 30 局稀疏奖赏的对局估出的优势基本是噪声，于是那一步有界更新会把部分信任域花在噪声上、下一次更新再把它部分抵消掉，这就是那 ±2 个百分点的震荡。估计误差按 1/√N 下降，升到 838.9 万之后这些条目每个也能拿到约 460 局，连罕见匹配都还有信息量，几乎整步都是信号。天花板落在"每次更新的改进量等于每次被噪声拉回的量"那个交点上，所以 rollout 越大天花板越高。最难的流派胡地从 21% 涨到 58%，如下图所示。

## 5. 天梯结果

天梯有 90% 的对局按 Elo 配对、其余从全榜随机抽取，但 API 并不标注某一局属于哪一种，所以只能近似划分。在我最后 2,000 局里，双方分差的分布一直衰减到 200 分左右然后走平，所以我把分差超过 200 的算作随机配对：在我最后 2,000 局里，这条规则取出的正是**分数最低的那 10% 对手**，共 200 局。剩下 **1,800 局 Elo 配对的胜率是 53.5% [51.2, 55.8]**。最能说明"赢在策略而不是卡组"的证据：**74 局配对到完全相同 60 张牌的对手——71.6% [60.5, 80.6]**，而对其他厄诡椪–蜜集大蛇牌表的 144 局只有 54.2%。按对手构筑划分的胜率如下图所示。

## 6. 尝试过但没有用的操作

**MCTS 没有用。** 我在引擎的搜索 API 上做了根并行的定型化 MCTS：对隐藏信息采样四种定型，每一种开一棵树跑 PUCT，用策略网络当先验、评论家当叶子估值，最后选根节点访问数最高的动作。它的胜率低于纯策略网络，所以最终提交的只有策略网络。一个原因是预算：一次前向在我的机器上要 15–22 ms，就算按 2.5 秒的上限算，每棵树也跑不到 40 次模拟，不足以比先验做得更好。更深的问题在定型化本身：每棵树都把采样出的那副手牌当成确定的，各自规划各自的路线，但真实对局里我只能对四种猜测出同一手棋，所以增加模拟次数只会把这个错位搜得更实。

**扩大模型。** 加宽主干后，BC 准确率和池内胜率几乎没有变化：前瞻列已经把每个选项**做了什么**写成了显式输入，本该用来背诵卡牌行为的容量无事可做。而且模型大一倍就意味着每小时决策数减半，而 §4 表明那条轴当时还在带来提升。

## 7. 可以提升的点

**训练吞吐。** 赛后对 actor 做剖析：策略前向占 **95%** 的墙钟时间，引擎自身的规则推进只占 **0.2%**。一块 GPU 批量跑同一个网络是约 1,900 决策/秒，单线程 CPU 只有 45–60；我 150 个 actor 合起来才 2,830，采集期间 8 块 GPU 全程闲着。改成推理服务器，每小时决策数大约能提升 3 倍。

**训练时间的安排。** 最后时间太紧，只来得及把这一套卡组训完，没有余力去试别的卡组，所以两个最终提交只能交同一个模型。
