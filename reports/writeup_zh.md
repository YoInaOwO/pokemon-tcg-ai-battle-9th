# 把前瞻做成输入，而不是搜索

**副标题：** Simulation 赛道 6,807 队第 9 名，金牌。一个 780 万参数的策略网络，对局时不做任何搜索。

**摘要。** 两个最终提交用的是同一套厄诡椪–蜜集大蛇卡组、同一份权重。训练跑在一台 8 卡 4090 的机器上，配 150 个 CPU actor，最后那次 PPO 花了 56 小时。核心做法是让每个合法选项先在引擎里试走一步，把走完之后的公开结果整理成 28 列特征接在这个选项后面，网络看到的就是这张卡**干了什么**，不用去背它的 id。训练分两段，先在 13.6 万局回放上做行为克隆，再对着一个照天梯还原出来的对手池跑 PPO。提升最大的一项是 rollout 规模；对局时加树搜索反而更弱。

感谢 Kaggle 和全体主办方办了这样一场竞争激烈的比赛。

## 1. 卡组：厄诡椪–蜜集大蛇

先分清两个词。**流派**指共用同一套核心的一族牌表，凡是围绕多龙巴鲁托 ex 搭的都算 `dragapult`；**精确卡组**指具体的那 60 张。8 月 12 日的竞技场里只有 14 个流派，精确卡组却有 148 套，光 `dragapult` 就占了 15 套。

**打法。** 纯草能量加速。*Teal Dance* 和 *Ripening Charge* 每回合免费贴一张基本草能量，*Wild Growth* 让贴上去的每张按两份算，两个招式又都是每能量加 30 伤害，第 3–4 回合就能一击带走 330 血。

| 角色 | 卡 | 理由 |
|---|---|---|
| 攻手 | 4 厄诡椪 ex、2 蜜集大蛇 ex | 免费贴能，伤害随能量成长；厄诡椪还是基础宝可梦 |
| 引擎 | 2 大竺葵线、4 活力之森、14 草能量 | Wild Growth 让每次贴能收益翻倍；活力之森让草系登场当回合就能进化 |
| 稳定性 | 4 捕虫套装、4 高级球、2 宝可平板、2 小光、4 莉莉艾的决心、2 喵喵 ex | 一张卡同时补能量和宝可梦 |
| 回收 | 夜间担架、水莲的援助、2 老大的指令、审判官、不公印章、狐大盗 ex | 被击倒之后把能量捞回来，老大的指令负责点下一个目标 |
| 非 ex 后手 | 2 大竺葵（140）、卡璞·哞哞（220） | 不吃"只对 ex 免伤"那一类效果 |

**为什么选它。** 我把每日回放（7 月 14 日到 8 月 12 日，13.6 万局）按流派分了类。用得最多的五个流派里，厄诡椪–蜜集大蛇的天梯胜率最高，904 局 53.9%，多龙巴鲁托 52.5%，长毛巨魔 44.1%。我取了它使用最多的那套精确卡组，当时有 26 支队伍在用。牌表公开，天梯上经常撞到一模一样的 60 张，卡组一样时胜率差就只能来自策略，正好用来衡量模型好坏。它的弱点是结构性的：攻手全是 ex，仙子伊布的 *Safeguard* 一张就能全关掉。

## 2. 模型结构

网络结构见下图。

![模型结构](writeup_fig1_arch.png)

*模型结构*

**Token。** 观测编码成 64 个 token：全局、选择上下文、场地各一个，18 个场上位置，30 张手牌，8 张"正在查看"的卡，两个弃牌堆袋，再加事件摘要、全局记忆、我方未露面牌库这三个。每个卡位是一个 **CardRepr**，由可学习的 id 嵌入和静态特征投影拼成；静态特征包括 HP、属性、进化阶段、ex 标记，以及人工校对过的特性和招式语义 schema。训练时按位随机丢掉 id 那一半，冷门卡就只能靠文本读懂。序列过 5 层 pre-LN Transformer（d = 384），池化成状态 *h*。

**选项是一等公民。** 每个合法选项有自己的嵌入，由它本身的特征向量，加上它指向的卡、目标、招式一起拼成。这个嵌入再去和状态 token 做交叉注意力，"目标：后场 3 号位"这种选项因此能读到那个位置当前的血量和能量。打分用 `logit = MLP([opt, h, opt ⊙ h])`，多选提示另外走一个计数头。

## 3. 特征工程

原则是**把选项讲清楚，而不是让网络背卡**。凡是只能从 id 记住的信息，一律写成数值喂进去。下表的维度写成"浮点列数 + 整数 id 数"两部分。

| 区块 | 维度 | 内容 |
|---|---|---|
| 全局 | 40 + 21 | 回合与动作计数、先后手标记、支援者/场地/贴能/撤退是否已用；双方牌库、手牌、奖赏、弃牌、后场数量；前场特殊状态；15 个流派的**对手卡组后验** |
| 场上 ×18 | 32 + 4 ids | 是否存在、是否已知、血量与已受伤害、本回合登场、能量数与属性、道具、进化深度；宝可梦、道具、能量 id |
| 手牌 / 查看 / 弃牌 / 牌库袋 | ids | 30 张手牌 id；8 张翻开的卡；弃牌堆做掩码均值；我方 60 张减去所有可见区域 |
| 事件 + 记忆 | 26 + 26 ids | 自上次决策以来：出过的招式、击倒、公开进入对手手牌的卡。累计：打出与贴能次数、双方各最近 4 次攻击、12 张已知卡 |
| 选项 | 60 + 28 | 类型、区域、序号、卡/目标/招式 id、归属、对数刻度计数、目标血量与能量，**外加 28 列引擎前瞻** |

**引擎前瞻。** 主阶段的每个选项都在引擎的搜索沙盒里执行一次，把执行后的公开结果读出来：打了多少伤害、有没有击倒、双方各拿几张奖赏、手牌和牌库变了多少、是否交回合、有没有直接分出胜负。在这之上再做两件事，一是把强制连锁和掷币按概率展开成宏动作，二是算一个合法性差分，看执行完之后有多少招式变得可用。这样"这张卡能让蜜集大蛇的招式打得出来"就成了明写的输入，不用当连招背下来。隐藏区域用固定种子的填充卡顶替，测试验证过填充卡不会漏进特征；同一份探针在训练和线上推理里跑的是同一段代码。

## 4. 训练

**第一阶段，行为克隆。** 数据是 13.6 万局里双方的每一个决策点，每个点都跑一遍探针。天梯回放的玩家水平参差很大，所以要给样本加权：赢家 1.0、输家 0.3，按时间做 10 天衰减，对局评分高的再上调。这里先训一个覆盖 14 个流派的共享基座，再微调出 12 个流派锚点；剩下两个流派太冷门，不值得单独做，超级雪妖女只占 0.4% 的席位，超级妙蛙花一局都没出现过。为什么不给每个流派单独从头训？因为数据量撑不住。什么时候贴能、什么时候进化、什么时候撤退、支援者留到哪一手，这些和卡组无关，要拿整个语料才学得稳，而单个流派只占语料的百分之几。

**第二阶段，价值头微调。** PPO 的优势等于回报减 V(s)，评论家没校准的话，最开始那几步有界更新追的是价值误差，不是策略改进。BC 训出来的价值头不能直接拿来用，它没见过策略自己会走到的状态。所以把厄诡椪–蜜集大蛇锚点的主干冻住，只放开两个价值分支，行棋逐位不变，再用冻住的策略打 1.2 万局，把两个评论家回归到最终胜负上。

**第三阶段，PPO。** 策略就从上一步那个模型出发。对手池照着天梯实际会给你配什么来搭：

- **70% 竞技场还原。** 我从开始训练那天（8 月 12 日）的回放 zip 里统计了每一套**精确卡组**的占比，把排名前 40 的按原比例复现，每一套都交给它所属**流派**的第一阶段锚点来开。比如那天最热门的是一套玛俐的长毛巨魔，占全部对局的 19%，在这一块里就占 21%，由 `marnie_grimmsnarl` 锚点驾驶；其余各套一直排到 0.4%。
- **10% 变异牌表。** 在流派内换掉 5–10 张，每套都用引擎校验能不能正常打，让一个称职的驾驶员去开一副略微跑偏的牌。这一块和下面的脚本一样，都是为了应付天梯上从全榜均匀抽取的那 10% 对局。
- **10% 脚本智能体。** 主办方给的四套入门卡组，由随卡组一起提供的脚本驾驶。低分段确实有人把主办方的脚本原样交上去。
- **10% 镜像。** 自身快照，另外每 20 次更新把较旧的快照加进一个联赛。

**纯自博弈不可行。** 双方开同一套 60 张，模型只会打内战，而完全相同的 60 张在我的天梯对局里只占 4%。要的恰恰相反：让它见过并打赢尽可能多的竞技场卡组，所以对手池里九成不是我这套牌。

γ 0.997，λ 0.95，clip 0.2，lr 1e-4。GAE 由先知评论家驱动；奖赏差塑形和对第一阶段锚点的 KL 惩罚都在前 8 次更新里退火到零。

**决定最终模型的是 rollout 规模。** 每次更新采集的决策数从 13.1 万提到 52.4 万，整条学习曲线都抬高了，不只是终点：任何相同预算下，52.4 万那条都比 13.1 万高 3–6 个百分点。既然这条轴有效，最终训练直接设成 **838.9 万**，是 52.4 万的十六倍。它前期按样本算更慢，累计 4,000 万决策时只有 0.62 的池内胜率，同期 52.4 万已经到 0.72；但它一直在涨，我提交的就是它最好的那个 checkpoint，4.03 亿决策、47 小时处的 **0.83**，而 52.4 万那条在 0.72 附近就走平了。三条曲线见下图。

*rollout 规模对比：每次更新 13.1 万 / 52.4 万 / 838.9 万决策*

**为什么单位样本的效率会下降。** PPO 是一步一步改进策略的，每一步都封了顶：clip 0.2、3 个 epoch、KL 提前停止。一步能走多远由信任域说了算，和这一步用了多少数据无关。所以一次训练从 D 个决策里榨出多少改进，取决于它走了几步，rollout 为 N 时就是 D/N 步。前期优势很大（第 1 次更新平均 |优势| 0.35），52.4 万的批量已经足够把一步走满，十六个小步叠起来的效果，一个大步给不了。累计 4,000 万决策时，52.4 万配方走了 **76** 步，838.9 万只走了 **5** 步。

**为什么天花板会更高。** 训练后期反了过来。策略已经接近对手池的均衡，平均 |优势| 掉到 0.16，信号变小了，而洗牌、掷币和隐藏信息带来的方差没变。对手池有 69 个条目，最冷门的每个只占 0.4% 的对局，52.4 万的 rollout 分给它们每个只有约 30 局。30 局稀疏奖赏估出来的优势基本是噪声，这一步会把一部分信任域花在噪声上，下一次更新再抵消掉一部分。估计误差按 1/√N 下降，rollout 提到 838.9 万之后，这些条目每个能拿到约 460 局，冷门匹配也有信息量了，一步下去几乎全是信号。天花板就落在每次更新的改进量和被噪声拉回的量相等的地方，rollout 越大，这个交点越高。最难的流派胡地从 21% 涨到 58%，见下图。

## 5. 天梯结果

天梯有 90% 的对局按 Elo 配对，其余从全榜随机抽，但 API 不标注某一局属于哪一种，只能自己近似划分。分差的分布一直衰减到 200 分左右然后走平，所以我把分差超过 200 的算作随机配对。在我最后 2,000 局里，这条规则挑出来的正好是**分数最低的那 10% 对手**，共 200 局。剩下 **1,800 局 Elo 配对，胜率 53.5% [51.2, 55.8]**。最能说明赢在策略而不在卡组的，是碰上一模一样 60 张牌的那 74 局，**71.6% [60.5, 80.6]**；对其他厄诡椪–蜜集大蛇牌表的 144 局只有 54.2%。按对手构筑分的胜率见下图。

## 6. 试过但没用的

**MCTS 没用。** 我在引擎的搜索 API 上做了根并行的定型化 MCTS：对隐藏信息采样四种定型，每种开一棵树跑 PUCT，策略网络当先验、评论家当叶子估值，最后选根节点访问数最高的动作。它的胜率低于纯策略网络，所以最终只提交了策略网络。一个原因是预算不够：一次前向在我机器上要 15–22 ms，按 2.5 秒的上限算，每棵树也跑不到 40 次模拟，赢不过先验。更根本的问题在定型化本身：每棵树把自己采到的那副手牌当成板上钉钉，各算各的最优线，可真实对局里我只能对四种猜测出同一手棋。多跑几次模拟，只会把这个错位算得更实。

**加大模型。** 主干加宽以后，BC 准确率和池内胜率都没什么变化。前瞻列已经把每个选项干了什么明写出来了，本来要拿去背卡的容量没事可做。而且模型大一倍，每小时决策数就减半，而 §4 说明那条轴当时还在继续带来提升。

## 7. 还能改的地方

**训练吞吐。** 赛后剖析了一个 actor：策略前向占 **95%** 的墙钟时间，引擎推规则只占 **0.2%**。一块 GPU 批量跑网络约 1,900 决策/秒，单线程 CPU 只有 45–60，而我 150 个 actor 加起来才 2,830，采集的时候 8 块 GPU 全闲着。改成推理服务器，吞吐大概能到 3 倍。

**时间安排。** 最后时间太紧，只够把这一套卡组训完，没余力再试别的，两个最终提交只好交同一个模型。
